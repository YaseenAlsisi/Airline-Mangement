# Clean Implementation Plan

## 1. Current Size Diagnosis

The project is about 85MB, but almost all of that size comes from generated build output, not from the source code or the module structure.

Current largest size contributors:

| Path | Approx. Size | Decision |
|---|---:|---|
| `backend/target/aams-0.0.1-SNAPSHOT.jar` | 83.77MB | Not needed in source control; generated by Maven |
| `backend/target/` | 84.56MB | Not needed; complete Maven build output |
| `.gradle/` | 0.78MB | Local Gradle cache; not needed |
| `build/` | 0.12MB | Gradle build output; not needed |
| `frontend/` | 0.29MB | Important frontend source code |
| `backend/src/` | 0.12MB | Important backend source code |

Conclusion: the real project source code is small. The large size is caused mainly by `backend/target`, especially one generated jar file.

## 2. Files And Folders Safe To Delete

These paths are generated artifacts and can be deleted safely because they can be recreated by running the build again:

```text
backend/target/
build/
.gradle/
```

Expected result after deleting them: the project size should drop from about 85MB to less than 1MB, without removing actual source code.

Suggested cleanup commands for Windows PowerShell:

```powershell
Remove-Item -Recurse -Force backend\target
Remove-Item -Recurse -Force build
Remove-Item -Recurse -Force .gradle
```

Important: do not delete `gradle/wrapper/gradle-wrapper.jar`. It is intentionally kept by the root `.gitignore`.

## 4. Files That Need A Decision Before Deletion

The project currently contains more than one build system:

```text
backend/pom.xml
build.gradle
settings.gradle
gradlew
gradlew.bat
gradle/
```

The real backend appears to be a Maven project because the actual application dependencies and Spring Boot configuration are in `backend/pom.xml`.

The root Gradle files look inconsistent with the current project:

- `settings.gradle` names the root project `demo`.
- `build.gradle` uses Spring Boot `4.1.0`, while `backend/pom.xml` uses Spring Boot `3.3.2`.
- `build.gradle` does not define the `backend` or `frontend` modules.
- The `group` value in `build.gradle` is unusually long and looks generated incorrectly.

Recommended decision:

If the project will continue using Maven:

```text
Delete build.gradle
Delete settings.gradle
Delete gradlew
Delete gradlew.bat
Delete gradle/
```

If the project should become a Gradle multi-module project later, keep these files for now, but rewrite them properly.

Current recommendation: use Maven for the backend and npm/Vite for the frontend. Remove the root Gradle files only after confirming no one depends on them.

## 5. `.gitignore` Improvements

The current root `.gitignore` already ignores:

```text
.gradle
build/
```

However, it does not explicitly ignore `backend/target/`, which is the main reason generated jar and class files may remain in the project.

Add these rules:

```gitignore
# Maven
target/
**/target/

# Frontend
frontend/node_modules/
frontend/dist/

# Environment files
.env
.env.*
!.env.example

# OS files
.DS_Store
Thumbs.db
```

## 6. Actual Cleanup Implementation Plan

### Phase 1: Capture A Before-Cleanup Snapshot

Goal: confirm the current size distribution before deleting anything.

Inspection command:

```powershell
Get-ChildItem -Force | ForEach-Object {
  $size = if ($_.PSIsContainer) {
    (Get-ChildItem $_.FullName -Recurse -Force -File -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum
  } else {
    $_.Length
  }
  [PSCustomObject]@{ Name=$_.Name; SizeMB=[math]::Round($size/1MB,2) }
} | Sort-Object SizeMB -Descending
```

### Phase 2: Delete Build Artifacts

Delete generated files only:

```powershell
Remove-Item -Recurse -Force backend\target
Remove-Item -Recurse -Force build
Remove-Item -Recurse -Force .gradle
```

Do not delete anything inside:

```text
backend/src/
frontend/src/
frontend/public/
```

### Phase 3: Update `.gitignore`

Add the Maven, frontend, environment, and OS ignore rules listed in section 5.

After editing `.gitignore`, verify that generated files do not appear again in Git:

```powershell
git status --short
```

Note: during inspection, this folder did not appear to be a Git repository. This command may fail until the project is opened from a folder that contains `.git`.

### Phase 4: Standardize The Build System

Recommended setup:

- Backend: Maven using `backend/pom.xml`
- Frontend: npm/Vite using `frontend/package.json`

After confirming Maven is the official backend build tool, remove the root Gradle files:

```text
build.gradle
settings.gradle
gradlew
gradlew.bat
gradle/
```

Only perform this step after confirming the project is not expected to be built with Gradle.

### Phase 5: Clean Incomplete Placeholder Modules

The backend is currently organized into feature modules/packages:

```text
accounting
agent
airline
auditlog
auth
calculation
common
excelimport
note
pricelist
report
transaction
user
```

Some packages currently contain only `package-info.java` and no real implementation:

```text
accounting
auditlog
calculation
excelimport
```

Recommended decision:

- If these modules are planned for upcoming work, keep them and document them as placeholders.
- If they are not required, delete them to reduce confusion.

Note: deleting these placeholder packages will not significantly reduce the project size, but it will make the structure clearer.

### Phase 6: Review Frontend Assets

The frontend is already small, and there is no obvious asset-size problem.

Review these files only if they are not used:

```text
frontend/src/assets/react.svg
frontend/src/assets/vite.svg
frontend/src/assets/hero.png
frontend/convert.mjs
```

Check usage before deleting:

```powershell
rg "react.svg|vite.svg|hero.png|convert" frontend
```

If there are no imports or references, unused assets/scripts can be removed.

### Phase 7: Run Verification After Cleanup

Backend:

```powershell
cd backend
mvn clean test
```

Frontend:

```powershell
cd frontend
npm install
npm run build
```

If `npm install` creates `frontend/node_modules/`, that is normal. It should remain local and must not be committed.

## 7. Priority Order

1. Delete `backend/target/` because it accounts for almost the entire project size.
2. Delete `.gradle/` and `build/` because they are cache/build output folders.
3. Update `.gitignore` to prevent the same problem from returning.
4. Decide whether the project is officially Maven-only or Gradle multi-module.
5. Remove unused placeholder backend modules if they are not planned.
6. Remove unused frontend assets/scripts after checking references.
7. Run backend tests and frontend build.

## 8. Expected Result

After Phase 2 only:

- The project size should drop from about 85MB to less than 1MB.
- No source code should be removed.
- The project should still be buildable because deleted files are generated artifacts.

After Phase 4:

- Build tooling becomes clearer.
- New developers will know whether to use Maven or Gradle.

After Phases 5 and 6:

- The project structure becomes cleaner.
- Unused placeholders and frontend files stop creating confusion during development.

## 9. Final Recommended Action

Start with the safe cleanup only:

```text
backend/target/
build/
.gradle/
```

Then update `.gitignore`.

After that, decide whether the project is officially Maven or Gradle. Based on the current repository state, Maven is the better choice because `backend/pom.xml` is the complete and active backend build file.
